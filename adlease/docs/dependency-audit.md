# Dependency audit (unused packages)

Audited on the `feature/adlease-local-hardening` branch, based on `main` at
commit `e3c574f` (29 October 2026). **Audit only: no package was removed.**

## Method

1. Take every entry under `dependencies:` in `pubspec.yaml` (27 entries).
   Exclude `flutter` and `flutter_localizations`, which come with the Flutter
   SDK, leaving **25 hosted packages**.
2. A package is a **candidate** if no file under `lib/` or `test/` contains
   `package:<name>/`.
3. For each candidate, also search the committed platform files (generated
   plugin registrants for macOS, Linux and Windows) and the rest of the
   repository for other references.

Result: **16 candidates**. The other 9 (`provider`, `shared_preferences`,
`intl`, `uuid`, `crypto`, `percent_indicator`, `flutter_animate`,
`google_fonts`, `package_info_plus`) are imported and in use.

## Why nothing was removed in this step

- **Not needed for this step.** Removing packages is not required to turn off
  backup or to correct the referral wording.
- **The lockfile would change.** Removing any package changes `pubspec.lock`,
  which CI requires to match. That needs `flutter pub get` with Flutter 3.47.8
  to regenerate and verify it, and the generated plugin registrants for
  macOS, Linux and Windows would also change.
- **Native code.** Unused plugins with native code are still registered and
  built into the app. That is a size and attack-surface cost, but removing
  them changes the build, so it belongs in its own reviewed PR.
- **Planned use.** The Firebase packages, `google_sign_in`,
  `flutter_secure_storage` and possibly `url_launcher` may be needed by the
  proposed backend, authentication and privacy work.

## Suggested follow-up (needs approval)

A separate cleanup PR that removes the clear candidates (`cupertino_icons`,
`fl_chart`, `shimmer`, `cached_network_image`, `device_info_plus`,
`share_plus`, `image_picker`, `path_provider`, `connectivity_plus`), with
`pubspec.lock` and the plugin registrants regenerated by Flutter 3.47.8 and
the full CI run. This audit does not say which Android permissions each
plugin adds; that should be checked in the merged manifest during that PR.
